# Supported SQL

Unsupported input is **rejected, not weakened**. A case with an unsupported query is reported
`UNSUPPORTED` (in a suite) or raises an error that names the construct (`check` with PostgreSQL or
DuckDB), never silently downgraded.

## Queries

Every query is one read-only `SELECT`.

| Supported | Rejected |
|---|---|
| Joins (`INNER`, `LEFT`), filters, grouping, aggregates, `DISTINCT`, `ORDER BY`, `LIMIT` | More than one statement, or empty SQL |
| Non-recursive CTEs, subqueries including correlated `EXISTS` and `IN`, `CASE`, `HAVING` | DDL, DML, `PRAGMA`, `ATTACH`, `DETACH`, transactions, extension loading |
| `UNION`, `INTERSECT`, `EXCEPT`, selected window functions, casts to supported types | `VALUES` as the top-level statement |
| | PostgreSQL and DuckDB: recursive CTEs, user-defined functions, ambiguous references, anything outside the allowlist |
| | Queries that time out, exceed the result-row cap, or cannot be compared under the requested column policy |

Queries run on in-memory copies with parser validation, `query_only`, an authorizer, a progress
handler deadline (`--timeout`, default 30 s) and a result-row cap (`--max-result-rows`, default
10,000).

## Schemas

=== "SQLite"

    - Database file or DDL. A file whose tables are all empty is treated as schema-only.
    - Schema-only generation supports single-column integer, text and UUID keys; `INTEGER`, `INT`,
      `SMALLINT`, `BIGINT`, `TEXT`, `VARCHAR(n)`, `CHAR(n)`, `REAL`, `DOUBLE`, `NUMERIC` and
      `DECIMAL(p,s)`, `BOOLEAN`, `DATE`, `TIMESTAMP`; and simple foreign keys. Other schemas fall
      back to simpler synthesis.
    - Column defaults and simple `CHECK` forms (`col IN (...)`, `col >= number`) guide generation.
    - PostgreSQL DDL passed with `--engine sqlite` is rejected.

=== "PostgreSQL and DuckDB"

    - DDL only, unqualified tables, a single-column `SMALLINT`, `INTEGER`, `BIGINT`, `TEXT`,
      `VARCHAR` or `UUID` primary key. Primary and foreign keys can be inline or table-level, and a
      foreign-key column must match the referenced key's type.
    - Columns: those key types plus `NUMERIC`/`DECIMAL`, `REAL`, `DOUBLE PRECISION`, `BOOLEAN`, `DATE`,
      `TIMESTAMP`, `TIMESTAMPTZ`. `VARCHAR(n)` length 1 to 10,000; `NUMERIC(p,s)` precision 1 to
      1,000 and scale 0 to the precision.
    - Single-column `UNIQUE`, literal defaults, `GENERATED BY DEFAULT AS IDENTITY`, and `CHECK`
      constraints (column or table level).
    - Not supported: composite primary keys, composite or cyclic foreign keys, foreign-key actions,
      non-literal defaults, other type parameters, `GENERATED ALWAYS AS IDENTITY`. If your suite
      needs composite keys, [open an issue](https://github.com/isitright-ai/isitright/issues): demand
      from a real suite decides what gets added.

## Known limitations

- **The search is heuristic.** It is not a proof of equivalence or an exhaustive state exploration.
- **No window-specific [mutations](../concepts/worlds-and-mutations.md#mutations).** Window functions run natively, but agreement for a window query
  covers only the states tested.
- **Complex rules may be skipped.** Complex `CHECK` expressions, regular expressions,
  trigger-dependent invariants, virtual tables, views and cyclic generation dependencies may be
  skipped or reported `INCONCLUSIVE`.
- **Ordering.** `--ordering auto` treats a top-level `ORDER BY` on the *reference* query as ordered;
  candidate-only ordering is ignored. Ties without a complete key may still have engine-dependent
  order.
- **Collations.** Collation behavior is delegated to the engine; comparison does not reproduce custom
  collations.
- **Reproductions** keep table DDL and standalone unique indexes. Performance-only indexes and
  triggers are omitted.
- **[Replay](../guides/replay-and-export.md)** applies a 30-second deadline and a 10,000-row result cap per recorded query. It is for
  isitright-generated reports and fixtures, not a general sandbox.
- **Trusted validators** run your Python; never load one from an untrusted file.
- This is a supported subset, not a claim of complete PostgreSQL compatibility.

[`NOT_FOUND_WITHIN_BUDGET`](../concepts/evidence.md#divergence_status) means only that no disagreement was observed in the states actually
tested. It is never a claim that the queries are equivalent.
